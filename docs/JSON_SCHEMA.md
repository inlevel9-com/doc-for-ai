# 출력 JSON 구조 (`docforai/1.0`)

어떤 원본(HWP, DOCX, PPTX, XLSX, PDF, ZIP, 그림, 소리…)이든 같은 모양으로 나옵니다. AI 학습·검색 파이프라인은 이 한 가지 구조만 알면 됩니다.

```jsonc
{
  "schema": "docforai/1.0",
  "source": {
    "file_name": "2026년 업무계획.hwp",
    "format": "hwp",                       // hwp | hwpx | docx | pptx | xlsx | xls | pdf | zip | jpg | mp3 | …
    "size_bytes": 184320,
    "sha256": "3ea41d…",                   // 중복 제거·출처 추적용
    "modified": "2026-03-02T01:12:00+00:00",
    "converted_at": "2026-11-05T07:52:33+00:00",
    "engine": "<변환 엔진 이름과 버전>"
  },
  "metadata": { "title": "…", "author": "…", "created": "…", "modified": "…", "format_version": "5.0",
                "entries": ["문서/메모.txt", "…"] },   // entries 는 ZIP 에서만: 변환한 안쪽 문서 경로
  "markdown": "# 2026년 업무계획\n\n가. 추진 배경 …",   // .md 파일과 같은 본문(프런트매터 제외)
  "blocks": [                               // 본문을 순서대로 쪼갠 것
    { "type": "heading",   "level": 1, "text": "2026년 업무계획" },
    { "type": "paragraph", "text": "가. 추진 배경 …" },
    { "type": "table",     "header": ["구분", "예산"], "rows": [["홍보", "1,000"]] },
    { "type": "list",      "ordered": false, "items": ["항목1", "항목2"] },
    { "type": "image",     "alt": "image", "path": "2026년 업무계획_files/BIN0001.png" },
    { "type": "code",      "language": "json", "text": "{\n  \"a\": 1\n}" },   // JSON·XML 원문처럼 줄 구조를 지켜야 하는 내용
    { "type": "slide",     "number": 2 }    // PPTX 에서만: 슬라이드 경계
  ],
  "tables": [ /* blocks 중 table 만 모은 것 */ ],
  "chunks": [                               // RAG·파인튜닝 입력 단위 (제목 경로 기준, 기본 최대 1,500자)
    { "id": 1, "heading_path": ["2026년 업무계획", "1. 추진 배경"], "text": "…" }
  ],
  "sheets": [                               // 엑셀, 표 형태 JSON, ZIP(안의 엑셀)에서 제공되는 시트별 레코드
    { "name": "예산", "header": ["부서", "항목", "금액"],
      "records": [ { "부서": "총무과", "항목": "사무용품", "금액": 120000 } ] }
  ],
  "warnings": [ "스캔 PDF 이면 OCR 이 필요합니다." ]
}
```

## 설계 원칙

- **원문 보존 우선**: `markdown` 은 가공하지 않은 전체 본문. `blocks`·`chunks` 는 거기서 파생되므로 언제든 다시 만들 수 있다.
- **표는 두 번**: Markdown 표(사람·LLM 용)와 `header/rows`(프로그램 용). 병합 셀은 왼쪽 위 칸에 값을 두고 나머지는 빈 문자열.
- **청크는 의미 단위**: 글자 수가 아니라 제목 구조를 따라 자르고, 너무 길 때만 문단 단위로 나눈다. 각 청크에 `heading_path` 가 있어 문맥 없이도 "어느 문서의 어느 절"인지 안다.
- **숫자는 숫자로**: 엑셀 레코드에서 `120000.0` 은 `120000` 으로, 날짜는 ISO 문자열로.
- **PDF**: 표의 내용은 텍스트로 추출합니다. 구조화된 `tables`는 Markdown 표가 생성된 문서에서 제공됩니다.
- **JSON 입력**: 최상위가 같은 모양의 객체 목록(또는 그런 목록 하나를 담은 객체)이면 표 블록과 `sheets` 레코드로, 아니면 들여쓰기한 원문을 `code` 블록으로 둔다. 문법이 틀린 파일은 원문 그대로 싣고 `warnings` 에 적는다.
- **XML 입력**: RSS 2.0·Atom 피드는 `# 피드 제목` 아래 글마다 `## 제목`, `날짜:`, 본문으로 푼다. 그 밖의 XML 은 정리한 원문을 `code` 블록으로 둔다. 외부 엔티티·DTD 는 해석하지 않는다.
- **ZIP 입력**: 안의 문서를 이름순으로 각각 변환해 `# 경로/이름` 제목 아래 잇고, 안쪽 문서의 제목은 한 단계씩 내린다(`#`→`##`). 그림은 `원본이름_파일명` 으로, 시트는 `원본이름/시트명` 으로 이름을 붙여 충돌을 피한다. 지원하지 않거나 실패한 항목은 건너뛰고 `warnings` 에 적는다. 압축 안의 압축은 한 단계까지.
- **그림·소리 입력**: 본문은 `| 항목 | 값 |` 메타데이터 표 하나다. 그림은 크기·색상 모드·EXIF(촬영 일시, 카메라, 위치 등)·PNG 텍스트 조각을 적고 원본 그림을 `image` 블록으로 연결한다. 소리는 태그(제목·아티스트·앨범 등)와 길이·샘플레이트·채널·비트레이트를 적는다. 글자 인식(OCR)과 음성 인식은 하지 않으며 `warnings` 에 그 사실을 남긴다.

## Markdown 파일 머리(프런트매터)

```yaml
---
source_file: "2026년 업무계획.hwp"
format: hwp
title: "2026년 업무계획"
author: "기획조정실"
converted_at: 2026-11-05T07:52:33+00:00
sha256: 3ea41d…
---
```

## JSON → Excel 매핑 규칙

`docforai to-excel 파일.json` 또는 GUI 의 **JSON → 엑셀로 되돌리기…** 는 이 프로그램이 만든 JSON(`schema` 가 `docforai/` 로 시작)만 받아 같은 이름의 `.xlsx` 를 만듭니다. 규칙은 단순하고 예측 가능하게 두었습니다.

### 공통: `정보` 시트

첫 시트는 항상 `정보` 이며 `항목 | 값` 두 열입니다. `schema`, `source.*`(파일 이름, 형식, sha256, 변환 시각 등), `metadata.*`, 그리고 `warnings` 가 한 줄에 하나씩 들어갑니다.

### 원본에 `sheets` 가 있으면: 시트 복원

엑셀·표 형태 JSON·ZIP 속 엑셀처럼 `sheets` 가 있는 문서는 **시트를 그대로 복원하고 끝냅니다.** `본문`·`표N` 시트는 만들지 않습니다(같은 표가 두 번 들어가는 것을 막기 위해).

- 시트마다 워크시트 하나. 첫 행은 `header`, 그 아래 `records` 를 순서대로. 레코드에 없는 열은 빈 칸.
- 시트 이름은 엑셀이 허용하지 않는 문자(`[ ] : * ? / \`)를 `_` 로 바꾸고 28자에서 자르며, 겹치면 `_2`, `_3` 을 붙입니다.
- 값은 JSON 그대로입니다. 숫자는 숫자, 참/거짓은 불리언, `null` 은 빈 칸. 날짜는 ISO 문자열(`2026-11-05T09:00:00`)로 남으며 엑셀 날짜로 바꾸지 않습니다.

### `sheets` 가 없으면: `본문` 시트 + `표N` 시트

`blocks` 를 순서대로 `본문` 시트에 한 줄씩 씁니다. 열은 `순번 | 종류 | 수준·번호 | 내용` 입니다.

| 블록 | 종류 | 수준·번호 | 내용 |
| --- | --- | --- | --- |
| `heading` | 제목 | `level` (1~6) | 제목 글 |
| `paragraph` | 문단 | (빈 칸) | 문단 글 |
| `list` | 번호목록 / 글머리목록 | 항목 번호 (1부터, 항목마다 한 줄) | 항목 글 |
| `table` | 표 | `표1`, `표2`… | `n행 × m열 → 시트 '표1'` |
| `image` | 그림 | (빈 칸) | `alt: path` (alt 가 없거나 path 와 같으면 path 만) |
| `slide` | 슬라이드 | 슬라이드 번호 | (빈 칸) |
| `code` | 코드 | 언어 | 코드 전체 |

표 블록은 등장 순서대로 `표1`, `표2`… 워크시트가 되며 첫 행이 `header`, 아래가 `rows` 입니다. 셀 수가 모자란 행은 빈 칸으로 채웁니다. 표 셀 값은 모두 문자열입니다(Markdown 표에서 왔으므로).

### 공통 안전 규칙

- `=` 로 시작하는 글은 수식이 아니라 **문자열**로 저장합니다.
- 엑셀이 받지 않는 제어 문자는 지우고, 셀 하나가 32,767자를 넘으면 잘라내고 `warnings` 로 알립니다.
- 첫 행은 굵게, 틀 고정(`A2`), 열 너비는 내용에 맞춰 10~60자 사이로 둡니다.
- 이 프로그램이 만들지 않은 JSON 은 "docforai JSON 이 아닙니다" 로 거부합니다. 임의의 JSON 을 엑셀로 만들고 싶으면 먼저 그 JSON 을 변환(JSON → docforai JSON, 객체 목록이면 `sheets` 가 생김)한 뒤 되돌리면 됩니다.
