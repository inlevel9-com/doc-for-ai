# docforai JSON → 엑셀

## 언제 쓰나

- 사용자가 올린 JSON 의 최상위에 `"schema": "docforai/1.0"` 이 있을 때.
- 요청이 "엑셀로 만들어", "표만 뽑아", "부서별 시트로", "합계 행 넣어", "원본 표 순서대로" 처럼 표 형태 산출물을 원할 때.
- JSON 이 이 형식이 아니면 이 스킬을 쓰지 말고 일반적인 방법으로 표를 만든다.

## 입력 구조 (요약)

자세한 구조는 `reference/json-schema.md` 에 있다. 엑셀을 만들 때 보는 곳은 넷이다.

| 키 | 내용 | 엑셀로 옮길 때 |
| --- | --- | --- |
| `source`, `metadata` | 파일 이름, 형식, 제목, 작성자, 변환 시각 | `정보` 시트(항목·값) |
| `sheets` | 원본이 엑셀·표 형태 JSON 일 때만. 시트마다 `header` 와 `records`(열 이름 → 값) | 시트를 그대로 복원 |
| `blocks` | 본문을 순서대로 쪼갠 것. `heading`, `paragraph`, `list`, `table`(`header`, `rows`), `image`, `code`, `slide` | 표 블록은 각각 시트로, 나머지는 `본문` 시트 |
| `tables` | `blocks` 중 `table` 만 모은 것 | 표만 필요할 때 바로 쓴다 |

`sheets` 가 있으면 `blocks` 의 표는 같은 내용이 중복된 것이므로 둘 다 넣지 않는다.

## 절차

1. **의도를 먼저 정한다.** 요청이 모호하면 한 번만 묻는다. 흔한 갈림길: 표만 필요한지 본문도 넣을지, 표마다 시트로 나눌지 한 시트에 이어 붙일지, 숫자 문자열(`"1,000"`)을 숫자로 바꿀지, 합계·정렬·필터가 필요한지. 묻지 않아도 될 만큼 분명하면 바로 만든다.
2. **기본 규칙으로 먼저 만든다.** `scripts/json_to_excel.py` 를 실행하면 프로그램의 버튼과 똑같은 결과가 나온다.
   ```bash
   pip install openpyxl
   python scripts/json_to_excel.py 보고서.json -o ./out
   ```
3. **의도에 맞게 다듬는다.** openpyxl 로 결과 워크북을 열어 고치거나, `document_to_workbook()` 을 불러 워크북 객체를 받은 뒤 시트를 합치고·지우고·열을 바꾼다. 자주 하는 손질:
   - 숫자처럼 보이는 문자열(`"1,000"`, `"12.5%"`)을 숫자로 바꾸고 표시 형식을 준다. 바꾼 사실을 사용자에게 알린다.
   - 같은 머리글을 가진 표 여러 개를 한 시트로 이어 붙이고 `출처` 열(표 번호 또는 상위 제목 `heading_path`)을 더한다.
   - 병합 셀이 풀린 표(왼쪽 위에만 값, 나머지 빈 칸)는 빈 칸을 위 값으로 채울지 사용자에게 확인한다.
   - 제목·문단이 필요 없으면 `본문` 시트를 지운다.
4. **검증한다.** 시트 수, 각 시트의 행·열 수, 원본 표 수(`tables` 길이)가 맞는지 세어 보고 결과와 함께 적는다.
5. **파일 이름**은 원본 JSON 과 같게(`보고서.json` → `보고서.xlsx`) 두되, 사용자가 다른 이름을 말했으면 그것을 쓴다.

## 지켜야 할 것

- 원본에 없는 값을 만들어 넣지 않는다. 계산(합계·평균)을 더할 때는 수식이 아니라 값으로 넣고, 어떤 열을 어떻게 계산했는지 적는다.
- `=` 로 시작하는 글은 문자열로 저장한다(수식 주입 방지). 스크립트가 이미 그렇게 한다.
- 셀 하나는 32,767자까지다. 넘치면 잘렸다고 알린다.
- JSON 의 `warnings` 가 있으면(스캔 PDF, 배포용 한글 문서 등) 결과를 전하면서 함께 알린다. 내용이 비어 있는 이유가 거기에 있다.
- 이 스킬은 파일 안의 내용만 다룬다. 인터넷에서 무엇을 찾아 채우지 않는다.
